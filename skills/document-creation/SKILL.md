# Document Creation

Create or update architecture docs, diagrams, and Confluence pages.

> **Reference**: For complete workflow, see `workflows/document-creation.md`

## Quick Reference

### Before Writing
1. Identify the audience (developers, stakeholders, ops)
2. Define the scope — what's in and out
3. Choose format (Markdown, Confluence, diagram)

### Structure
1. **Overview** — what this covers and why it matters
2. **Context** — system/component background
3. **Details** — the actual content
4. **Diagrams** — visual representations
5. **Links** — related docs and resources

### Diagrams
- Use PlantUML, Mermaid, or similar text-based tools
- Keep diagrams version-controlled with code
- Include diagram source, not just rendered images

### Review
- Technical accuracy first
- Clarity for target audience
- Completeness (what's missing?)
- Freshness (update when code changes)

## When to Apply

- Creating architecture documentation
- Updating technical docs after changes
- Writing runbooks or operational docs
- Creating Confluence pages
- Drawing architecture diagrams
