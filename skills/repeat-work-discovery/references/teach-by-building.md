# Teach by building

Read this when the user is new to skills, or cannot name anything to automate.
The fastest way to understand a skill is to watch a small one get built from the
user's own rough material, then redirect it to their real weekly task. Do the
exercise in the conversation; save nothing until step 6.

## Contents

1. Read the house conventions
2. Draft a small example skill in front of the user
3. Ask which task they really repeat
4. Rewrite the skill for that task
5. Live-test before saving
6. Save and report

## 1. Read the house conventions

Before drafting, read how skill files are written in this repository (front
matter keys, description style, size and layout). A skill that ignores the
conventions gets rewritten later.

## 2. Draft a small example skill in front of the user

Pick a harmless transformation the user can follow: rough notes turned into a
one-page summary. Write the skill live and narrate its parts in one line each:

- **Steps**: what to do, in order (read the notes, group them, write the page).
- **Format**: the exact shape of the output (title, three headings, bullets).
- **Rules**: what to always or never do (keep the user's wording for decisions,
  mark unknowns instead of guessing).

Show the finished file in a few lines, not a lecture. The point is that a skill
is a short written procedure plus an output template.

## 3. Ask which task they really repeat

Ask one question: "Which task do you repeat most weeks?" If they hesitate,
offer three example shapes:

- a weekly status write-up;
- meeting notes turned into follow-up actions;
- a weekly pass over new postings that updates an analysis file.

Let them pick or describe their own. Ask for one real example input and the
output they would be happy with.

## 4. Rewrite the skill for that task

Replace the example's steps, format and rules with the ones for their task,
using their sample input and desired output. Keep the description specific
about when it should trigger.

## 5. Live-test before saving

Run the rewritten skill on the sample (or a second real input) and show the
result. Fix what the user points out. A skill saved untested usually fails the
first time it matters.

## 6. Save and report

Save it where the user's skills live, say where, and say how to trigger it.
Finish by offering the discovery scan: "Want me to look through your mail and
calendar for the next five things worth automating?"
